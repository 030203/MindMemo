# 2026-06-03 开发日志

## 今日完成

- 明确 AI 对话链路的核心问题与优化方向。
  - 当前对话链路存在“所有 query 默认走 RAG 检索”的问题。
  - 当前系统 prompt 对“必须基于当前记录/文档回答”的约束过强，导致通用问题被误解释为文档问答。
  - 已确定本次优化的核心目标不是继续调 embedding，而是增加 `intent router`，先判断问题意图，再决定是否检索、是否绑定当前记录、是否需要追问。
- 输出 intent router 详细优化方案，并整理为可执行待办。
  - 将对话请求拆分为 `DOC_QA`、`DOC_OP`、`GENERAL_CHAT`、`GENERAL_KB_OR_TOOL`、`AMBIGUOUS` 五类意图。
  - 明确执行链路从“单链路 RAG”调整为“Router -> Direct / RAG / Tool / Clarify”多分支模式。
  - 确认 prompt 需要拆分为 Router Prompt、Direct Prompt、Grounded Doc QA Prompt、Clarification Prompt 四类，而不是单一全局强约束 prompt。
- 落地后端 intent router 修复与按需检索分支。
  - 扩展 `QueryRoute`，新增 `should_retrieve`、`should_use_active_context`、`should_ask_clarification` 等显式控制字段。
  - 修复 active context 抢占问题：当前页面打开记录/文档时，不再把 `你是谁`、天气类问题、联网类问题默认解释为文档问答。
  - 新增 `direct` 与 `clarify` 路由，支持直接回答和短澄清，不再所有问题都落到 memory RAG。
  - 天气和联网问题在工具不可用时会明确说明需要外部数据源，不再回退成记忆检索。
  - 普通上下文兜底文案去掉“基于这条记录...”机械前缀，改成更自然的直接表述。
- 继续完成第二轮路由升级。
  - 在 `QueryRoute` 中新增 `retrieval_scope` 与 `answer_mode`，把“不检索 / 当前文档 / 当前记录 / 全局知识库”显式化。
  - 当前文档上下文内新增 `document_op` 路由，区分 `doc_summary`、`doc_extract`、`doc_rewrite`、`doc_rewrite_weekly_report`、`doc_rewrite_email`、`doc_translate`。
  - 文档改写、周报整理、翻译请求不再混入普通 detail QA，而是走全文 transform 路径。
- 补齐前端 trace 标签与回归验证。
  - `ChatPage` 增加 `direct / clarify / weather_tool_unavailable / web_tool_unavailable` 标签显示。
  - 新增回归测试，覆盖“文档页里问你是谁”和“带 `context_memory_id` 问天气”两个误路由样例。
  - `ChatPage` 继续补充 `retrieval_scope / answer_mode / document_op intent` 展示。
- 完成第三轮 prompt 分层。
  - `llm_answer_service` 新增 `answer_mode` 入参，支持按模式切换 system prompt / user prompt。
  - 目前已区分 `grounded_qa`、`grounded_review`、`summarize`、`extract`、`transform` 五类 prompt 语义。
  - 文档总结、证据问答、内容改写不再共用同一套提示约束。
