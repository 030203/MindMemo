# 分阶段开发路线图

## 总原则

不要一口气做太多。每一阶段只解决一个主要风险点，并要求：

1. 范围明确
2. 可验证
3. 不破坏上一阶段稳定性
4. 留有回退空间

## Phase 0：标准与骨架

### 目标

建立需求、文档、日志、前后端骨架与基本运行能力。

### 当前状态

已完成。

### 退出条件

- 文档与项目结构稳定
- 前后端基础服务可访问

## Phase 1：真实数据层替换

### 目标

将内存 mock store 替换为 PostgreSQL + SQLAlchemy 核心数据层。

### 当前状态

核心接口已经切换到 SQLAlchemy 持久化层。为了保证本地开发稳定，当前默认使用 SQLite，本地或部署环境可通过 `DATABASE_URL` 切换到 PostgreSQL。

### 只做这些

- `users`
- `memory_items`
- `todos`
- `timeline_events`
- `review_queue`
- session / repository / service 基础链路

### 先不做

- pgvector
- 文件解析
- 复杂 Agent 编排

### 退出条件

- 前端现有页面不改接口即可读取真实数据库
- CRUD 能跑通
- 无 mock store 主链路依赖
- 本地默认持久化链路已稳定，可随环境切换到 PostgreSQL

## Phase 2：用户与权限隔离

### 目标

补齐登录、注册、JWT 和 `user_id` 级数据隔离。

### 当前状态

后端已完成：

- 注册
- 登录
- `/auth/me`
- Bearer token 解析
- token 级 `user_id` 数据隔离

为了不打断现有前端开发，当前仍保留 `ALLOW_DEV_DEMO_USER=true` 的开发兜底模式。后续前端接入登录后，可以逐步收紧该能力。

### 只做这些

- 登录/注册
- token 鉴权
- service / repo 层用户隔离

### 退出条件

- 所有核心查询都基于登录态用户
- 不允许跨用户读写数据
- 开发兜底模式只作为过渡能力存在

## Phase 3：RAG 基础检索

### 目标

加入 `memory_chunks + pgvector`，把 QA 从 mock 改成真实召回。

### 当前状态

已完成第一小步：

- `memory_chunks` 已落库
- 新建记忆会自动生成 chunks
- 历史记忆会在启动时自动回填缺失 chunks
- QA 已从 chunk 层做第一版基础召回

当前仍未完成：

- 真实 embedding 生成
- PostgreSQL/pgvector 向量召回
- 基于 LLM 的最终答案生成

### 只做这些

- chunk
- embedding
- 基础向量检索
- metadata 过滤
- 引用来源返回

### 先不做

- 复杂 rerank
- GraphRAG

### 退出条件

- 能基于真实记忆回答“最近有哪些重要事情”
- QA 返回 citations

## Phase 4：文件与 URL 摄取

### 目标

支持 PDF 和 URL 内容进入记忆系统。

### 只做这些

- 文本型 PDF 抽取
- URL 正文抽取
- 清洗后写入 memory ingest

### 退出条件

- 至少一条 PDF 和一条 URL 可进入 QA 检索范围

## Phase 5：提醒与后台任务

### 目标

让系统具备基础主动能力。

### 只做这些

- reminder scan
- 定时任务
- in-app / PushDeer 基础提醒
- review queue 持久化

### 退出条件

- TODO 临期可触发提醒
- 每日总结任务可运行

## Phase 6：稳定化与交付

### 目标

打磨演示闭环、修回归问题、补文档和部署说明。

### 退出条件

- 演示脚本可完整走通
- 核心页面可用
- 核心链路有验证记录

## 当前建议执行步骤

Phase 0-6 已经形成 MVP 可验收闭环。后续不再继续扩展普通 TODO / 管理后台能力，而是进入 AI Agent Personal Memory & Workflow System 的长期演进路线。

下一步严格执行：

1. 阅读 `docs/standards/11_AI_Agent长期演进路线图.md`
2. 从 Phase 7：Memory Intelligence Layer 开始
3. 每次只选择一个可验证的小切片
4. 优先建设结构化事实、检索评估和 Agent workflow 可观测性

历史 MVP 执行顺序：

1. 真实数据层
2. 权限隔离
3. pgvector 检索
4. 摄取
5. 提醒
