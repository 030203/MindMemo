# 技术实现规范

## 后端规范

1. 使用 FastAPI。
2. API 路由统一放在 `backend/app/api/v1/`。
3. 业务逻辑放在 `services/`，不要直接写在路由里。
4. 数据访问放在 `repos/`。
5. 数据结构定义放在 `schemas/`。
6. ORM 模型放在 `models/`。

## 前端规范

1. 使用 React + TypeScript。
2. 页面放在 `frontend/src/pages/`。
3. 通用 UI 组件放在 `frontend/src/components/`。
4. API 调用放在 `frontend/src/api/`。
5. 避免把业务逻辑塞进单个大组件。

## 数据与接口规范

1. 后端响应统一格式：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

2. 时间字段统一使用 ISO 8601。
3. 所有业务表默认保留 `user_id`。
4. 所有新增结构化字段优先考虑：
   - 是否需要索引
   - 是否需要 review
   - 是否需要 timeline

## AI 与 RAG 规范

1. 结构化输出优先 JSON。
2. QA 结果必须带引用来源。
3. 检索不足时，允许回答“不足以判断”。
4. 高风险自动化只做建议，不直接执行。

## 代码变更规范

1. 每次只处理一个小切片。
2. 变更前明确入口文件和受影响模块。
3. 变更后至少执行一项验证：
   - build
   - import check
   - API smoke test

## 当前推荐的核心路径

1. `backend/app/services/store.py` 先逐步拆到 repository + service
2. `backend/app/models/` 逐步接真实数据库
3. `frontend/src/api/` 保持前后端契约稳定
