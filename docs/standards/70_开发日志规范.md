# 开发日志规范

## 目的

开发日志不是流水账，而是为了保证项目节奏稳定、可回溯、可继续。

## 存放位置

- 目录：`dev_logs/`
- 文件命名：`YYYY-MM-DD.md`

## 必填内容

### 1. 今日完成

只写已经落地的内容，不写计划。

### 2. 验证记录

写清做了什么验证，例如：

- build 成功
- 接口返回正常
- 页面可访问

### 3. 风险 / 阻塞

包括：

- 未完成的关键链路
- 当前技术风险
- 环境问题

### 4. 明日待办

只写下一步最重要的 1~4 项。

## 书写要求

1. 事实化
2. 简洁
3. 与仓库实际变化一致
4. 不要把远期规划混进明日待办

## 更新时机

1. 每次完成一个明确开发切片后更新
2. 每天结束前至少更新一次
3. 自动化任务每日补充或生成当天日志
