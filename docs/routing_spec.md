# 路由判定规范 (Routing Spec)

**版本**: v2.0
**日期**: 2026-06-27
**用途**: Router 的 fast/slow 判定准绳，同时作为路由测试集的标注依据。

---

## 0. 适用前提（重要）

MindMemo 是「第二大脑」，对话链路**围绕用户自己记录的内容**。
路由器判定遵循一条核心原则：

> **所有涉及个人记录的事都走 slow（ReAct），fast 路径只有纯聊天+外网工具查询，不做检索。**

因此路由测试集只包含对话场景，排除以下两类：
- **通用知识问答**（"什么是闭包"、"HTTP 和 HTTPS 区别"）——不是产品核心场景，不纳入路由评测。
- **记录 CRUD**（"帮我记一下…"、"待办：明天开会"）——走记录窗口，不进对话路由器。等以后做成 tool 再单独评测。

---

## 1. 二分类定义

### fast — 纯聊天 + 外网工具查询

**特征：不需要访问用户的任何记录。** 系统只需要聊或调个外网 API。

| 子类 | 说明 | 例 |
|------|------|----|
| 闲聊/问候/告别 | 单轮社交回应 | "你好"、"晚安"、"谢谢" |
| 情绪表达 | 单纯的感叹/分享心情 | "累死了"、"今天好开心" |
| 外网工具查询 | 查天气/搜网页等纯外部 API | "北京今天天气怎么样" |

### slow — 所有涉及个人记录的事

**特征：需要检索 Memory 才能回答。** 走的链路是 ReAct（一到多轮，端到端统一）。
最简单的查一条和复杂的跨记录分析，本质上都经过「搜索→读→答」循环，不拆两套。

| 子类 | 说明 | 例 |
|------|------|----|
| 单点检索 | 查一条记录/一个事实点 | "我记过妈妈生日吗"、"上次那条 Docker 笔记重点是啥" |
| 时间罗列 | 单一时间窗枚举 | "我昨天记了啥"、"上周有哪些笔记" |
| 状态确认 | 查待办状态 | "那个待办我做完了吗"、"本周记了几条" |
| 分析/规律 | 跨记录找模式/趋势 | "分析我这个月学习规律"、"我最近情绪变化趋势" |
| 归纳/总结 | 跨记录压缩提炼 | "总结我半年的读书笔记提炼三条" |
| 对比/评估 | 比较多对象 | "对比我记的两个健身方案" |
| 规划/建议 | 基于记录推建议 | "怎么改进学习方法"、"帮我规划下月阅读" |
| 复盘/反思 | 多步因果 | "复盘这次项目为什么失败" |

## 2. 规则优先级（从上到下裁定）

```
1. 空输入 → fast
2. 慢意图关键词（分析/规划/总结/对比/复盘/怎么办/建议我/给我建议/有什么建议/帮我想...）→ slow
3. 个人域信号 → slow  (核心新增：检测到任何记录/笔记/日记/待办/记过/查/有没有记等个人域词)
4. 闲聊/问候/情绪词 → fast
5. 「不知道为什么」→ fast（情绪表达消歧）
6. 长句未命中以上任何规则 → slow（辅助）
7. 以上都不命中 → 未覆盖，交 LLM 兜底
```

**关键修正**：
- 旧版规则中 lookup 和 timelist 属于 fast 已被纠正——它们涉及个人记录，现在归 slow。
- `<=12字` 规则已被删除。短句中的意图词（第2条）优先级高于长度。
- 「为什么」不再单独判 slow——它不涉及记录，不命中个人域信号。但「为什么我」命中个人域（个人行为分析），归 slow。

---

## 3. 测试集设计原则

- **标签准绳**：以本规范第1、2节为唯一依据。
- **覆盖用户群体**：话题横跨学习/工作/情绪/健康/生活/读书/灵感/人际/财务/育儿等。
- **口语化**：贴近真实输入，含省略、口语表达。

---

## 4. 评测口径

- **规则覆盖率** = 规则能判定的条数 / 总条数。
- **规则命中准确率** = 规则判对的条数 / 规则判定的条数。
- `uncovered` 不计入准确率分母，单独报告。
- 评测注入返回 None 的桩（不调真实 LLM），通过 `decided_by` 区分 rule 判定与 fallback。
